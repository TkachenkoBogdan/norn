The cache

Why a cache miss costs real money

Claude has no memory between turns. Every time you send a message, Claude Code sends the whole conversation again: the system prompt, every file it read, every reply it wrote. On a long thread that is hundreds of thousands of tokens, each turn.

What the cache is

The API keeps a copy of what it has just read. When the next request starts with the same text, it reads that copy instead of processing the text again. That read costs about a tenth of the normal price. The copy lives for a fixed time after its last use: one hour for Claude Code today (older versions used five minutes). Touch it in time and the clock restarts. Let it lapse, and it is gone.

Two things to hold on to:

  • The cache works on the beginning of the conversation. It matches from the first word up to the first thing that changed. Change something early, and everything after it is new again.
  • Writing to the cache costs more than a plain read, not less: twice the normal price for an hour-long copy. The saving comes from the reads that follow. A write that nobody reads back is pure cost.

What a miss is

A miss is a turn where the copy could not be used, so the whole context is processed, and written, again. It happens when:

  • The thread was quiet past the hour. You stepped away, came back after lunch, typed one line, and paid for the whole thread. This is the common one.
  • The thread switched model. Each model keeps its own cache. Opus cannot read what Sonnet wrote.
  • The thread compacted. The folded summary is new text; nothing before it matches any more.
  • Something early in the conversation changed: an edited system prompt, a different set of tools, a Claude Code update.

Why it matters more the bigger the thread

A miss costs the write price on everything in the context, not on the one line you typed. On a 5k thread you would never notice. On a 250k thread it is the price of a lunch.

What to do

  • Finish, or let it go. If you will not be back within the hour, the thread is cold anyway. Coming back to a big one costs its whole weight; a fresh thread for the new task is often cheaper.
  • One turn keeps it warm. A short message before the hour is up restarts the clock for the whole context. Norn tells you when a big one is about to expire.
  • Don't switch models mid-thread unless the switch is worth re-reading everything.
  • Compact on purpose, at a natural break, not in the middle of a task you will keep touching.
  • Keep the beginning stable. Project instructions and tools go first and stay put; what changes goes last.
